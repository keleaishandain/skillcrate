# SkillCurator V2 实施规划（工单制 · Codex 实施 · 监督审核）

> 模式（学习者 2026-08-10 指令）：监督者（Claude）做规划/工单/审核/验收，实施由本地 Codex CLI（`codex exec`）完成。
> 审计留痕：git 基线 + 每工单一个提交 + 本文件与 CURRENT_TASK.md 记录每次验收结论。

## 执行流水线（每张工单固定走）

1. 监督者起草工单 prompt（含背景、精确范围、红线约束、验收标准）
2. `codex exec -C <project-root> -s workspace-write -o <报告文件> "<工单>"`
3. 监督者审核：① `cargo check` / `npm run build` 零错误 ② `git diff` 逐文件审查（模块边界、红线）③ 功能冒烟
4. 通过 → commit `WO-N: <标题>`；不通过 → 返工单（**最多 2 轮**），仍不过则监督者接管修复并如实记录
5. 更新 CURRENT_TASK.md 与本文件的验收记录

## 全局红线（写进每张工单）

- 绝不写入 skills-manager 的 SQLite（E2/E6）；SkillCurator 状态只进 `~/.skill-curator/state.json`
- 永不真删除技能文件；删除类操作仅限工具/项目技能目录内的同步副本（E8）
- 不读取、不存储会话对话正文（PRD §7 隐私边界）
- 不改动已验收模块的既有行为（cluster/curation/usage/import），除非工单明确要求
- UI 中文、三态（加载/空/错误）齐全
