## 0. 一句话定位 ✍（导师依据学习者竞品反馈起草，待学习者采纳或改写）

> 自研的个人技能管理软件：复刻已验证的核心能力（Git/本地/市场三类来源导入、按包分组、启停并同步到 Codex / Claude Code / OpenCode），新增唯一差异化功能「**AI 辅助管理**」——用被动数据找出冗余技能、隔离区安全淘汰，让 20+ 技能存量"用得清楚、留得值得"。从头自建，作为学习者本人的项目。（学习者 2026-08-10 确认："收"）

## 1. 用户与任务 ✍（源自学习者 2026-08-10 口述，导师整理；☐ 一处待确认）

**画像（以学习者本人为原型）**：同时使用 Codex、Claude Code、OpenCode 三个 AI 编程工具的重度个人用户；每天打开 AI 工具完成科研、日常学习、求职与技能学习任务；技能从 Git 仓库、市场、本地零散装入，存量 63 个。

**痛点阈值**：技能超过 **20 个**后开始分辨不清——哪个管什么、重复了没有、哪个还值得留，全凭记忆，而记忆在这个规模上失效。

**触发事件（学习者确认 2026-08-10，推翻导师候选框架）**：主触发 = **要装新技能的时候**。本产品定位为技能安装的**统一入口**——"有了它就不从别处装了，直接打开它装并顺手管理"。

**设计含义（产品推断，源自上述确认）**：
1. 装是前门，管是进门后的顺手动作：管理功能寄生在安装时刻，不期待用户专程来管理
2. **安装时冗余拦截**：D4 第一段（静态分组）不依赖使用数据，可在安装当下提示"要装的技能与已有的 X 抢同一个活"——冗余功能第一展示位从"定期报告"前移进"安装流程"
3. 定期冗余报告降级为补充唤回手段，负责存量清理与慢变化（90 天行为数据裁决仍走报告）

## 2. 当前流程与痛点 ✍（学习者自述，导师结构化）

**没有本产品时的真实"流程"**：
1. **装**：从各处装入技能 → 装完即忘，没有清单概念
2. **用**："想起来哪个用哪个"——能被想起的永远是那几个，其余技能沉默积灰。深层痛点是**不可见**：不知道自己有什么、每个解决什么、哪些在重复
3. **清**：唯一的管理动作 = 偶然想起某技能没用 → 去磁盘目录里手动翻找并直接删除（高摩擦、凭感觉、删错不可恢复）

**现有替代品 Skills Manager 的边界（学习者实测结论）**：已解决"导入"和"分软件管理"（装与分发）；未解决"按包管理"和"AI 分析、整理、精简"（用与留），整体仍依赖用户手工操作。→ 本产品的差异化空间即在"用与留"。

## 3. 范围与非目标 ✍（依据 D2/D3/D4/D5，V1 边界被 D4 倒逼收敛）

**V1 必含（依赖推理：隔离区动作 = "从 agent 目录撤下/恢复同步"，因此启停同步被迫进 V1）：**
1. 导入管理：Git / 本地 / skills.sh 三类来源；包分组沿用**派生模式**（D1 翻案定稿：不落库，按来源现场分组，复刻自己修改版已验证的行为）
2. 启停与同步：技能/包级启停，同步到 Claude Code、Codex 两个工具（隔离区的前置依赖）
3. 冗余两段式：描述聚类分组 + 组内 90 天被动数据裁决 + 隔离区处置（D4 定稿）
4. 兼容现有 `~/.skills-manager` 库格式，63 个存量技能直接可管（D5 暂定，PRD 评审可翻案）

**V1 非目标（明确不做）：** 排行榜与市场浏览、弹窗交互规范、AI 问答管理（MCP）、两个以上工具适配、多设备同步 → 全部进 V2+ 待议

**形态（D2）：** 桌面 GUI 优先，保证可交互性

## 4. 主流程（分工：可沿用的标注"沿用"，新时刻学习者设计）

**总原则（学习者 2026-08-10 拍板）：基础流程沿用 Skills Manager 成熟模式，仅在差异化时刻做原创设计。**

### ① 装一个技能包

- 步骤 1-4 沿用 Skills Manager：粘贴 Git URL/选择本地目录/市场点装 → 解析来源 → 识别出包内 N 个技能并落库为 Package 实体（D1）→ 展示包详情
- **步骤 5（学习者 2026-08-10 拍板 D6：安装零拦截）**：安装过程不做任何冗余提示——"用户想装什么就装什么"，筛选全部后置到使用过程（D4 行为裁决 + 报告）。静态分组仍在安装后静默执行，仅更新分组数据，不打断流程。
  - 可选缓解（导师建议，非阻断，采纳与否学习者定）：库视图技能卡显示灰色"同职责组 ×N"角标，点击跳报告页——保持可见性、零打扰
- 步骤 6 沿用：选择启用范围（哪些 agent）→ 同步 → 完成态展示

### ② 停用一个包并同步（整条沿用 Skills Manager 模式）

包卡片 → 停用开关（或从预设移除）→ 同步引擎从所选 agent 目录撤下 → 卡片上 agent 徽标变灰确认终态。无原创设计点。

### ③ 冗余报告 → 确认隔离 → 反悔恢复（✍ 导师示范流程，S3，学习者可改任何一步）

1. 每周后台全量分析完成 → 托盘角标 + 系统通知："本周冗余分析：2 组建议处理"（用户凭通知知道有事）
2. 点开报告页：按"职责组"分卡片——组职责一句话（"这 3 个技能都在做论文润色"）、组内每技能的 90 天调用份额条、被标记者带黄标注原因（"90 天仅调用 1 次，份额 4%"）（用户凭数据知道为什么）
3. 点"隔离"→ 确认弹窗复述后果："将从 Codex、Claude Code 撤下；30 天内可一键恢复；文件不删除"（用户凭弹窗知道会发生什么）
4. 确认 → 卡片灰化移入"隔离区"页，同步引擎实际撤下，操作日志记一条（用户凭状态变化知道干成了）
5. 【反悔线】数天后发现某任务效果变差 → 打开隔离区页：每条显示"隔离于 X 天前，原同步到 Codex + Claude Code"
6. 点"恢复"→ 不弹确认（恢复是安全方向）→ 原目录、原同步状态原样重建，卡片回库并带"已恢复"角标 7 天（用户凭角标确认完整回归）
7. 隔离满 30 天 → 下次报告提示"可归档"，仍需手工确认，**永不自动删除**

### 流程层欠账

无 —— ①-5 以"零拦截"决策（D6）关闭，三条主流程全部定稿。

## 5. 失败路径与兜底 ✍（部分预填，学习者补≥3条）

- 误杀兜底：隔离非删除、30 天可恢复、永不自动删除、操作可追溯（D4 定稿）
- 冷启动：新技能 30 天观察期不裁决；组内样本 <10 次不裁决（D4 定稿）
- ✍ 同步失败（目录被占用/无权限）：仅该 agent 标记"同步失败"红点并可重试，不阻塞其他 agent；失败原因写操作日志
- ✍ 导入源失效（仓库被删/网络断）：报错并附原因与代理提示；已装技能不受上游消失影响（本地文件为真相源）；更新检查失败只显示"无法检查"，绝不误报"有更新"
- ✍ 调用日志解析失败/无数据：裁决自动降级为"观察中"——**数据缺失时宁可沉默，绝不给隔离建议**
- ✍ 索引损坏：SQLite 仅是索引，可从技能文件夹全量重扫重建（沿用 Skills Manager 架构原则）；技能文件本身走 git 备份

## 6. 成功标准与指标口径 ✍（引用 D4，学习者补产品级指标）

- 功能级：冗余口径见 D4 定稿（分组阈值 0.8 / 90 天窗口 / 份额 15% / 冷启动 30 天）
- ✍ 产品级（初值均为假设，上线后用真实数据校准）：
  - 北极星候选：**隔离建议采纳率**——报告给出的建议被用户确认的比例，衡量"判得准"
  - 护栏：**误恢复率**——被隔离后 30 天内又被恢复的比例，目标 <10%，超标说明裁决规则过激
  - 定位验证：**安装入口迁移率**——新增技能中经本产品安装的比例，验证"统一入口"（学习者确认的核心定位）是否真实成立
  - 可见性：30 天内被查看/管理过的技能占比——对照"想起来哪个用哪个"的原始痛点

## 7. 数据、成本、风险 ✍

- **数据与隐私边界（写死）**：只读取本机 Claude Code / Codex 会话日志中的技能调用事件（技能名、时间戳、会话 ID），不读取对话正文、不上传任何数据
- **成本（数量级估算，标注假设）**：63 技能 embedding 判重为一次性分钱级；LLM 复核边界对每周全量在 ¥1 量级内；桌面应用零运行成本
- **风险**：① 会话日志格式非官方稳定接口，agent 升级可能破坏解析（缓解：解析失败静默降级"观察中"）② 分组阈值 0.8 未校准，初期可能误分组（缓解：组支持手动拆分/合并，人工修正写回）③ 单人业余开发，范围失控是头号风险（缓解：D3 已把 V1 锁死四项）
